# G 검토와 운영 검증 후속 지시 — Codex, 2026-09-25

기준 HEAD `5f16d99`. 구현 담당자는 H1~H5 순서로 작업한다. 이번 Codex 작업은 검토·문서 작성이며 운영 데이터 변경, SEC/Gemini 호출, Telegram 전송은 수행하지 않았다.

## 판정

- 283개 테스트를 재실행해 통과했다. R1~R3의 주요 보완과 G의 수집·초안·카드 연결은 구현됐다. G 운영 실행은 아직 없다. 로컬 실자료 검증은 운영 검증과 구분한다.
- G의 인수는 **보류**한다. 인용 존재/숫자 문자열 검사는 통과하지만 금액 단위·통화·인과 관계가 틀린 문장이 통과하는 경로를 재현했다. 180초 예산도 모델 요청 내부 재시도까지 전달되지 않는다.
- '6기업/일'은 달성 보장이 아니다. 실제 한도는 재시도 포함 HTTP 요청 6회이며 성공 초안 수는 그보다 작을 수 있다. '문서 하루 최대 160KB'도 상한이 아닌 이번 표본 실측이다.
- 원문 확보 10/10은 수집 성과다. 그 원문이 기업의 이익 변화 설명에 적합한지와는 별도다. MPC에 MPLX 배당 전망만 붙은 경우를 초안 품질의 통과 사례로 세지 않는다.

## 인수인계 질문의 결정

1. 모델 429는 **즉시 재시도하지 않는다**. 모든 구성요소에 적용한다. 서버가 명시한 재시도 가능 시각이 있으면 기록하고, 없으면 다음 KST 날짜까지 자동 모델 요청을 보류하는 보수적 정책으로 시작한다. 제공자 오류를 보고 일일 한도 소진이라고 단정하지 않는다. 큐/기존 결과는 보존한다.
2. 6-K 관련성은 표 필수를 제거하되 재무 용어 개수만으로 수용하지 않는다. H3의 주체·기간·문서 목적 검사를 적용한다.
3. IR 보조 경로 미구현은 수용한다. SEC로 먼저 안정화하며 해외 후보를 조용히 제외하지 말고 미확보 사유를 보인다. 기존 스크리너 SEC 단일 요청과 새 수집기는 현재 직렬 실행이므로 별도 프로세스 제한기는 당장 통합하지 않아도 된다. 새 수집기의 redirect/재시도는 사전 통제한다.
4. import-context 뒤 review_needed/사람 확인 유지에 동의한다. 미검토 표시가 잘못된 숫자나 가이던스 분류를 허용하는 면책 수단은 아니다.
5. 원문·CTX·관측은 30일 동안 유지한다. 실제 누적 파일 수/압축 용량/처리 시간을 기록하고 이후 결정한다. 이번 159KB를 고정적인 하루 최대치로 쓰지 않는다. job 55분 확대는 우선 수용하되 180초 단계 예산의 대체 수단으로 쓰지 않는다.

## H1. 잘못된 숫자·인과 연결 차단 (최우선)

대상 `candidate_context.py`, prompt/parser version, 관련 테스트.

재현 입력: 원문 `Revenue was $5 million in 2025. The analyst consensus is presented elsewhere.`를 그대로 인용하면서 한국어를 `2025년 매출은 5 billion EUR입니다.`로 작성했다. check_claim/validate_draft는 이 문장을 수용했고 link=explicit_link도 유지했다. 숫자 집합 {5, 2025}가 같다는 것이 통화/단위/의미의 일치를 보장하지 않는다.

- 첫 버전에서는 자동 단위 환산을 금지한다. 금액/백분율/범위/괄호 음수/통화/지표/대상 기간을 원문의 같은 문단 또는 표 행·헤더에 연결한 구조로 추출한다. text_ko의 수치 문구는 검증된 토큰에서 결정적으로 렌더한다. 검증할 수 없으면 그 수치 주장을 보류한다. 문장에 같은 숫자가 있더라도 다른 기간/지표의 숫자를 옮겨 쓰지 못하게 한다.
- `period/currency/unit/gaap/kind` 메타데이터도 검사한다. GAAP 여부가 원문에 없으면 unknown. 전망을 실제 성과로, 자회사 배당을 모회사 EPS로 바꾸지 않는다. claims뿐 아니라 limitations에도 동일한 숫자/기간/전망 규칙을 적용한다. 자유로운 next_check는 질문/확인 계획만 허용한다.
- WORD_NUMBERS에서 may 같은 단어를 문맥 없이 5로 인정하지 않는다. 월/분기 문법이 확인된 경우만 정규화한다. 부호를 버리는 numbers 집합만으로 판단하지 않는다.
- 자동 생성 link는 당분간 **unconfirmed 또는 temporal_context만 허용**한다. explicit_link는 원문 문장 자체가 특정 추정치 수정과 사건을 연결하고 사람이 그 연결을 확인한 별도 근거에서만 표시한다. 본문 어딘가 analyst/consensus라는 단어가 있다는 검사는 삭제한다.
- prompt/parser 버전을 올려 잘못 수용된 기존 초안을 immutable 이력에 보존하되 현재 카드에서는 구버전 검증 초안으로 표시하거나 숨긴다. 새 검증 없이 기존 초안을 그대로 정상으로 이관하지 않는다.

필수 테스트: 위 재현, USD↔EUR, million↔billion, (5)↔5, 5%↔5달러, 과거/현재 기간 교환, GAAP↔non-GAAP, may 의미, 회사/자회사 주체 교환, 무관 consensus 단어, limitations의 잘못된 숫자. 검증 단계 자체는 모델 호출 없이 재현 가능해야 한다.

## H2. 요청 예산·마감·보류·실패 상태 일치

대상 extract.call_gemini_prompt, candidate_context.run_sources/run_drafts/main, company_filings.SecClient, daily_run_state, policy.

코드 확인 사항:

- run_drafts는 요청 전에만 deadline을 검사하고 공용 모델 함수에는 넘기지 않는다. 고정 timeout=60, 최대 4회 요청과 5/10/20초 대기는 남은 180초를 넘을 수 있다.
- main은 run_sources가 stale/partial로 held여도 run_drafts를 실행한다. 초안 대상도 현재 후보가 아닌 과거 성공 entry까지 포함한다.
- filing index/body HTTP 오류를 notes에만 남기고 아무 문서도 없으면 no_relevant_document로 마무리한다. 모델 실패만 발생해도 main의 최종 상태는 source 실패만 확인해 success가 될 수 있다.

구현:

1. 공용 모델 함수에 deadline/최대 시도 수를 전달한다. 요청·대기·재시도 직전에 잔여 시간을 검사하고 timeout=min(설정, 남은 시간)으로 설정한다. 남은 시간이 없으면 예약/네트워크 0. 응답 읽기까지 전체 마감을 확인한다. context는 첫 순회에서 기업당 1시도만 한다. 실패 기업은 다음 기업에 기회를 주고, 재시도는 다음 실행/다음 날 정책으로 돌린다. extract/cards의 503/네트워크 재시도는 최대 1회, 429는 공용 차단 상태로 즉시 중단한다.
2. 429 보류 상태를 model_budget과 함께 공유한다. 뒤의 cards/context가 같은 제공자에 연속 요청하지 않게 한다. 불명확한 원인은 provider_rate_limited로 표시한다. 요청 수/성공 초안 수/실패/보류를 별도 집계한다. 로컬 사본은 같은 API 키의 제공자 한도를 소비하지만 운영 원장의 예산과 동기화되는 것은 아니다. 추가 로컬 실호출 반복으로 검증하지 말고 앞으로 모의 검증을 우선한다.
3. held면 sources와 drafts 모두 신규 호출 0. 성공 문서가 있어도 현재 후보 목록과 대상 FY가 맞는 entry만 draft 큐에 넣는다. 오래된 CTX는 last_valid로 보존하되 source 실패/기간 불일치/구버전 검증을 카드에 표시하고 최신 확인 결과로 사용하지 않는다.
4. 원문 결과에서 정상 미확보(no_relevant_document)와 HTTP 접근 실패를 분리한다. 일부 확보 후 일부 실패는 문서를 쓰되 quality=partial, 전부 접근 실패는 failed. 본문을 못 읽고 '관련 문서 없음'으로 7일 대기시키지 않는다. drafts 실패/보류도 run_status와 coverage에 반영한다. 기술 실패의 다음 조사 기회는 24시간, 예산 보류는 다음 허용 기회, 정상 미확보는 7일이다.
5. SEC 요청은 대기 후에도 마감을 다시 확인한다. redirect는 자동 추적을 끄고 각 hop의 hostname(정확한 sec.gov 또는 .sec.gov 하위 도메인), 횟수, 예산을 **전송 전** 검사한다. 현재 URL suffix 검사와 urlopen 자동 redirect 뒤 사후 차감은 한도 보장이 아니다. 요청 시작 전에 일일 계수를 저장하는 callback을 두고 다음 auto가 중단 전 요청 수를 잊지 않게 한다. 기업 조사 슬롯도 시도 시작 시 예약한다.

필수 시험: 남은 2초의 모델 timeout, 429 뒤 다른 구성요소 호출 0, stale+기존 draft 대기 호출 0, 현재 후보 이탈/FY 변화, index/body 전부 503, 문서 1성공+1실패, source 성공+모델 전부 실패, redirect 한도·호스트, pace 중 마감, 중단 뒤 예산 유지. 실제 잠들지 않는 가짜 시계를 사용한다.

## H3. EPS 설명에 유용한 문서를 고르기

대상 company_filings.recent_filings/pick_documents/looks_like_earnings, candidate_context 관련 블록·초안 선정.

- 관련성은 두 단계다. (a) 해당 발행사의 공식 실적/전망 자료인가 (b) 그 문장이 후보 기업의 이익 변화 설명에 직접 도움이 되는가. 문서 수집 성공과 핵심 근거 확보를 분리한다.
- 발행사/연결 그룹/자회사/고객 등 claim 주체를 저장한다. 모회사 연결 이익·매출·마진·물량·가격·비용·주식 수에 관한 문장을 우선한다. 자회사 문장은 모회사 수익과의 연결 근거가 있을 때만 핵심 설명으로 쓰고, 연결이 없으면 보조 정보 또는 insufficient_earnings_context로 둔다. MPC/MPLX는 이 분류를 시험하는 고정 사례로 사용한다.
- 6-K는 표가 없어도 회사명/회계기간/실적 또는 가이던스 제목/본문 지표가 함께 확인되면 후보 문서로 허용한다. 배당 공지·인사 변경·투자자 행사·범용 위험 문구를 실적 자료로 수용하지 않는다. IR 경로 추가는 이번 범위 밖이다.
- EX-99 첨부파일 순서대로 세 개를 소진하지 말고 제출 목록의 제목·설명으로 실적/전망 문서 우선순위를 정한다. 재무 용어가 여러 개 나왔다는 이유로 관련성을 확정하지 않는다.
- 문서를 찾았다는 이유로 정기보고서를 무조건 생략하지 않는다. 핵심 실적/전망 설명을 확보했으면 생략해도 되고, 배당 전망만 있으면 남은 문서·크기·시간 예산 안에서 대체 자료를 확인한다. 무제한 추가 다운로드는 금지한다.
- 텍스트 블록 선택은 서두 순서보다 실적 변화/가이던스/원인/일회성/반대 근거를 우선하고 coverage 범위를 표시한다. 자동 주체·의미 검증은 완전하지 않으므로 상태명은 계속 '자동 정리·미검토'다.

시험/완료: 표 없는 정상 6-K, 관련 없는 EX-99, 자회사 배당만 있는 문서, 모회사 이익과 연결된 자회사 설명, 원문 부호·기간을 보존한 표, 기존 실제 10기업 표본의 재분류 결과. 새로운 Gemini 실호출 없이 문서 fixture와 이미 받은 결과부터 검증한다.

## H4. CIK 누락은 전체 재스크린 없이 해결

현재는 issuer 캐시가 없으면 기다린다. 이는 다음 정시 실행만이 해결 방법이라는 뜻이 아니다. 공용 SEC 목록 1회를 받는 bootstrap을 구현하면 가격/EPS 재조회나 신규 알림이 필요 없다.

- `candidate_context --refresh-issuers` 또는 공용 전용 함수를 만든다. 공식 SEC ticker/거래소/CIK 목록만 가져와 sec_issuers.json.gz에 원응답 hash와 관측시각을 저장한다. 기존 load_universe/store_issuers를 재사용하되 전체 screen main을 호출하지 않는다.
- 현재 스크린 원본·후보 ID·EPS/가격 관측일을 바꾸지 않는다. exact ticker+exchange만 연결하고 충돌은 보류한다. cache missing일 때 1회 자동 시도 가능하며 context HTTP/시간 예산에 포함한다. API 실패는 identity_unavailable로 명시한다.
- 한 번 unavailable로 기록됐다가 다음 실행에서 매핑을 확보한 경우, 이전 7일 next_eligible 때문에 계속 기다리지 않도록 identity 상태 변화가 조사 자격을 무효화하게 한다.
- 시험: 오래된 CIK 없는 snapshot+빈 캐시→SEC 목록 1회→매핑→기존 CAN-ID 유지, 조회 실패/충돌, unavailable 다음 실행 정상 복구, 전체 스크린 호출 0.

## H5. 전송 없는 첫 운영 검증과 반복 검증

구현 담당자가 H1~H4를 마친 뒤 수행한다. 'G 첫 실행에서 추가 자동 메시지 없음'은 **검증 실행의 전송을 차단하라**는 뜻이지 다음 날 정시 실행까지 기다리라는 뜻이 아니다. 정기 실행을 기다리는 것만으로 전송 차단이 보장되는 것도 아니다.

- workflow_dispatch에 `mode=context_verify`를 추가한다. 기존 daily/auto/commands 의미는 유지한다. 이 모드는 같은 writer concurrency·최신 checkout·테스트·복구를 사용하되 실행 단계는 issuer bootstrap → context → cards/views → persist → artifact로 명시한다. collect/extract/screen/telegram_cmd/notify/candidate_alerts/weekly_report는 실행하지 않는다.
- 전송 차단을 환경 플래그와 공용 send 경계에도 적용하고 이 job에는 Telegram 자격증명을 제공하지 않는다. 검증에 필요 없는 정상 일간 완료 상태를 success로 채우지 않는다. 별도 검증 run 기록을 남긴다. 실운영 데이터 수집·카드 저장은 이 검증의 목적이며, 사용자 추적 원장과 발송 원장은 변경하지 않는다.
- 1차: 캐시/CIK → 원문 → 초안 → 카드 단계별 상태와 실제 요청 수를 확인한다. stale snapshot이면 안전하게 held로 끝내고 숫자 스냅샷을 새것처럼 만들지 않는다. 새 snapshot이 필요한 경우 별도의 **screen 실행을 포함하되 동일 전송 차단을 유지하는 명시적 옵션**을 제공한다. 정상 auto를 강제로 실행해 우회하지 않는다.
- 2차: 신규 수집·모델 작업을 시작하지 않는 `verify-cache-only` 옵션으로 같은 자료 재렌더·저장 재실행. 데이터 조회 캐시, CTX 참조, 모델/SEC 일일 계수 불변, 알림 원장 불변, 기존 관측 파일 덮어쓰기 없음 확인. 정상 context 재실행은 남은 예산으로 다른 후보를 처리할 수 있으므로 무조건 '2차 호출 0'을 기대하지 않는다.
- 제공자 429/503이면 실패/보류 결과 자체를 운영 증거로 남긴다. 초안 성공률을 높이려고 한도·재시도·실호출 횟수를 즉석 확대하지 않는다. 다음 정상 실행에서 성공을 확인할 수 있도록 미확인 항목을 남긴다.

인수인계에는 H별 커밋, 회귀/재현 시험, 운영 run ID·단계·요청/성공/보류 수, 기존 AMCX 영수증·bootstrap·추적 3종목 불변, 실제/모의 확인 구분을 넣는다. 당시 데이터가 다른 날로 넘어갔다면 실제 실행 날짜로 적는다. 9/26 09:17은 dispatch 예정 시각이며 이미 성공한 실행처럼 쓰지 않는다.
