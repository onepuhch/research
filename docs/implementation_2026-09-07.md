# 투자리서치 개선 적용 결과

뉴스 수집 중심의 기존 흐름에 원문 검증, 가설 중복 방지, 실제 숫자 관측, 반증 점검, 판단 이력과 복구 절차를 연결했다. **코드·데이터·문서의 로컬 적용과 검증을 완료**했다. 원격 운영 전환과 접근 불가 컨센서스 확보는 완료로 표시하지 않는다.

## 감사에서 확인한 문제와 변경

| 문제 | 적용한 변경 | 확인 방법 |
| --- | --- | --- |
| 모델 오류가 키워드 신호로 변환 | 오류는 retry, 금융 문서 오탐은 rejected, 원문 인용 없으면 신호 불채택 | 모델 오류·대출 선급금·근거 인용 테스트 |
| 동일한 기각 문서 반복 호출 | source_state에 원문·해시·버전·상태·재시도 시각 저장 | 반복 기각·실패 재시도 테스트 |
| 대형 고객 발표 유실 | demand_evidence로 보존 | 수집 테스트 |
| 신호에서 연구 추적 단절 | 기업+가설 등록, 원신호 ID, 활성 아이디어 EPS 수집 대상 연결 | 중복 등록·별도 가설·watchlist 테스트 |
| 다른 FY·출처 비교 | 관측일과 대상 기간 분리, 기업·단위·통화·회계기준으로 시계열 분리 | 기간·출처·통화·backfill 테스트 |
| 유지 관측이 상향 이력 초기화 | 일별 관측 차이와 월간 연속 변화를 별도 계산 | 유지·동일 날짜 테스트 |
| 기사 한 건으로 중기 단계 | 신규 등록은 관찰, 중기는 실제 컨센서스 시계열 필요 | 승격 거부 테스트 |
| 예제가 운영 보고에 혼재 | example 격리, legacy 보존, live 출처 정의 | 마이그레이션·보고서 테스트 |
| 판단 변경 내역 유실 | 이유 필수, before/after와 리뷰를 복구 저널로 함께 저장 | 이력·저널 복구 테스트 |
| 명령 처리·알림 재시도 취약 | 6시간 처리 설정, durable queue, 14일 /track, 하루 후보 제한, 손상 상태 차단 | 응답 실패·재등록·일일 한도·메시지 길이 테스트 |
| 설계와 현재 코드 불일치 | AGENTS·원칙·README·운영 절차·보고서 템플릿 갱신 | 문서와 CLI 대조 |

## 실제 적용 사례

[CRDO 재점검](crdo_review_2026-09-06.md)에 공식 실적 2개 분기를 연결했다. actual/guidance 14개 관측을 등록하고 기존 잘못된 EPS baseline 해석을 수정했다. 컨센서스 미확보와 GAAP 마진 점검 필요가 보드에 노출된다. 기존 865개 신호는 삭제하지 않았으며 원래 필드 값을 보존했다.

## 검증 결과

- Python unittest 35개 통과. 네트워크·Telegram 전송은 모의 처리한다.
- 보고서 8종 실행, 평가 표본 생성, 알림·명령 dry-run을 포함한 12개 CLI 실행 성공.
- 백업 SHA-256 일치, 마이그레이션 반복 불변, 전체 테이블 컬럼·ID 검증 통과.
- git diff --check 통과. [기계 판독 검증 결과](verification_2026-09-07.json) 참조.
- 60개 티어별 평가 표본을 reports/generated/evaluation_queue.csv에 생성했다. 정답이나 적중률을 임의로 채우지 않았다.

## 운영 전환 전제와 후속 순서

1. 검증된 변경을 원격 main에 반영하고 첫 수집·추출·상태 저장을 확인한다. 로컬 테스트가 외부 API 성공을 보장하지 않는다.
2. FMP HTTP 402를 접근 권한 확인 또는 허용된 수동 출처로 해결한다. 이번 작업에서 요금제 구매는 하지 않았다. 수동 입력 형식은 [운영 절차](daily_run.md)에 있다.
3. CRDO를 2026-09-13에 재검토하고 동일 FY 컨센서스 관측을 축적한다. 단일 시점의 값으로 과거 상향을 추정하지 않는다.
4. 대기 표본의 원문 정확도·추가 연구 가치를 직접 판정하여 evaluation_log에 저장한다. 그 결과로 발견 임계값과 소스 범위를 조정한다.
5. 실제 관측 기간이 확보되면 30/90/180일 벤치마크 복기와 공급자 확장을 구현한다. 현행 PE 비교는 정확히 일치하는 90일 양끝 날짜가 없으면 자료 부족을 반환한다.

Google Sheets는 기존 탭을 보존하는 v2 전용 탭 연동 코드를 준비했지만 배포하지 않았다. 상태 쓰기는 단일 작성자 전제이며 Telegram 전송과 로컬 상태 저장 사이의 중단에 대해서는 정확히 한 번 전달을 보장하지 못한다. 원문 스냅샷 보관 기간 자동 삭제도 아직 구현하지 않았다.
