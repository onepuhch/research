# V1 결과 검토 — 기본 동작 수용, 식별·문구 보완

Codex, 2026-10-11. V1 결과 문서의8개 결정과 candidate_feedback/telegram_cmd/promote 코드를 읽었다. V1 시험23개를 직접 실행해 모두 통과했다(2.927초). 전체658개·GitHub CI는 구현 담당자 보고이며 이번에 다시 실행/조회하지 않았다. 실제 Telegram 답장 동작은 미관측이다.

## 8개 결정 판정

1. 원 알림 시각과 영수증 시각의10분 대조는 보조 확인으로 수용한다. 사용자 답장을10분 안에 해야 한다는 조건이 아니다. 다만 아래 식별 보완이 필요하다. 상수10분은 검증된 채팅/봇 식별 대체 수단이 아니다.
2. tracked_before를 보존해 중단 재개 결과가 already_tracked로 변하지 않게 하는 방향을 수용한다. 사용자 의도·실제 원장 등록·회신을 분리한 것은 적절하다.
3. 불일치 알림의 track 의도 기록과 rejected/disputed_source 결과 분리를 수용한다. 관심 판단이 실제 추적 등록을 의미하지 않는다는 표시를 유지한다.
4. candidate_id 있는 sent material_update 지원을 수용한다. 보고에서는 새 발굴 평가와 재검토 이벤트 분모를 필요에 따라 분리해야 한다.
5. JSON 손상을 입력 오류 회신으로 완료하지 않고 재시도에 남기는 수정은 수용한다.
6. 도움말 한 줄 추가를 수용한다.
7. 완료 큐에서 본문/action을 지우고 메시지 참조만 보존하는 방식을 수용한다.
8. invalid_record 거절은 저장 전에 판정된 영구 입력 오류에 한해 수용한다. 일반 ValueError 모두가 영구 거절이라는 전제는 두지 않는다. 기존 명령과 답장에 적용되는 track_result가 저장/원장 구조 오류까지 삼키지 않는지 호출 경로를 점검하고, 상태 오류는 재시도 예외로 보존한다. JSONDecodeError는 이미 별도 전파됨을 확인했다.

## 작은 보완1 — 식별 정보 누락은 연결 성공으로 처리하지 않기

정적 확인: candidate_feedback.resolve는 from_bot이 False일 때만 거절하므로 None을 허용한다. 영수증시각/답장대상시각 중 하나가 없으면 시각 검사를 건너뛴다. process_updates도 누락 필드를 None으로 큐에 넣는다. 따라서 보고의 '봇이 보낸 것이고 시각이10분 이내인 경우에만 연결'보다 실제 조건이 느슨하다. 실제 잘못 연결된 운영 사례를 확인했다는 뜻은 아니다.

- 운영 답장 경로는 from_bot=True와 유효한 원 메시지/영수증시각을 요구한다. 빠진 경우 원문에서 추측하지 말고 판단·추적 없이 명시적 ID 명령 안내로 끝낸다. 날짜 형식 오류도 예외 누출 없이 안내한다.
- from.is_bot은 '어떤 봇인가'만 알려 줄 뿐 우리 봇임을 보증하지 않는다. 이번 단일 허용 채팅에서 사용하되 채팅/봇 교체 시 기존 영수증에 자동 연결하지 않는 규칙을 README에 명시한다. 향후 scope를 변경/이전할 때 식별을 검증하고 이관한다.10분 휴리스틱으로 교체를 안전하게 지원한다고 설명하지 않는다.
- CLI --dry-run --reply-to의 자료 없는 조회는 진단용 미검증 조회로 따로 표시한다. 운영 resolve의 검증을 약화해 CLI를 지원하지 않는다.
- 시험: 운영 필드 누락·잘못된 시각·비봇·10분 밖은 쓰기0, 원래 메시지가 일치하면 며칠 뒤 사용자 답장도 정상, CLI dry-run 쓰기0.

## 작은 보완2 — 카드 변경과 숫자 변경을 구분

정적 확인: handle_reply(detail)은 candidate_version이 다르면 '알림 이후 숫자가 바뀌었습니다'라고 쓴다. 후보 버전에는 설명·출처·context·분류 등 숫자 이외 정보도 포함된다. 반대로 버전에 포함되지 않은 시세 등의 변화는 같은 버전이어도 가능하다.

최소 수정은 '알림 당시와 같은 카드 버전입니다/카드 내용이 변경되었습니다'로 문구를 바꾸는 것이다. 실제 EPS 필드 비교를 구현하지 않은 상태에서 숫자 변경/변화 없음이라고 단정하지 않는다. 새 비교 기능은 이번에 추가하지 않는다. 설명만 바뀐 버전과 동일 버전에 대한 회신 시험을 수정한다.

## 완료와 다음 작업

V1의 기본 설계와 기존23개 합성 동작은 수용하며 위 좁은 보완 후 구현 검토를 마친다. 파일은 candidate_feedback.py, telegram_cmd.py, test_v1_feedback.py, README 및 인수인계 범위다.8번 점검에서 상태 오류가 영구 거절로 끝나는 경로가 발견되면 해당 분기만 고친다. V2/V3·예약 시각 변경으로 확대하지 않는다.

실제 검증은 사용자가 자연스럽게 후보 알림에 답장한 다음 기존 명령 실행의 update→reply event→처리 결과→회신을 확인한다. 시험을 위해 관심없음/추적 판단을 강요하거나 대신 보내지 않는다. 사용자가 조회만 원하면 '자세히'는 판단과 등록을 바꾸지 않는다. 인증 로그를 못 읽으면 확인 불가로 남긴다.

429 해제15:00UTC=다음 KST 날짜00:00이라는 보고를 수용한다. 이 시각 변환과 차단 해제 후 실제 처리 여부는 별개다. 10/12 보류 규칙 첫 운영 확인도 별도 남긴다. 자동 관측 예약은 설정하지 않았다.

이번 변경은 검토 문서와 STATUS뿐이다. 코드/운영 원장 수정·모델 요청·실제 메시지 발송·push는 하지 않았다.
