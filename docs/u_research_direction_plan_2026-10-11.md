# U 방향과 실행 계획 — 후보 판단을 주작업으로

작성: Codex, 2026-10-11. 실행 담당: Claude, 판단 검토: Codex. 이번 문서는 작업 우선순위에서 S/T 계획보다 우선한다. 기존 운영 안전 규칙과 이미 인수한 수정은 유지한다.

## 목표와 기간

다음 한 주기의 목표는 **이익 변화가 실제 사업 변화인지, 지속될 근거와 시장 예상과의 차이가 있는지를 구별해 다음에 추적할 후보를 제시하는 것**이다. 후보 수·알림 수·시험 수를 연구 성과로 세지 않는다. 근거가 부족한 후보를 보류하거나 가설이 틀린 후보를 탈락시키는 것도 유효한 결과다.

작업 시작 후 3개 작업일 안에 1차 판정표를 만들고, 시작 후 7일 또는 아래 산출물 완료 중 먼저 오는 시점에 방향을 재점검한다. 이는 작업 일정이며 자동 실행 예약이 아니다. 장애 발생·새 실적 발표·thinking 평가 완료를 기다리지 않는다. 자료 접근 실패는 한계로 기록해 그날의 작업을 마친다.

작업 시간의 약70%는 후보 연구,20%는 발굴 방식 평가,10%는 운영 확인에 배정한다. 기록을 위한 별도 시간 계측 기능은 만들지 않는다. 실제 원장 손상·오발송 등 긴급 사고만 예외이며 중단한 연구 과제를 인수인계에 남긴다.

## U1 — 기존 세 주제의 1차 판단 (첫 산출물)

입력: S3 개정표, 발송 당시 카드·원문, 현재 저장 문서. 최신 사실이 결론에 필요한 경우 공식 IR/공시를 읽어 확인한다. 당시 알려진 사실과 이후 사실은 분리한다. 추가 Gemini 호출을 전제로 하지 않는다. 미추적 기업은 발굴 적격성 검토까지만 하며 장기 모델·목표주가 등 심층 검증으로 확대하지 않는다.

| 순서 | 주제 | 이번에 끝낼 질문 | 보류 조건 |
|---|---|---|---|
| 1 | PBF | 업황 개선·재가동·비용 절감·일회성 항목 중 어떤 변화가 지속 이익을 설명하는가? 예상치 상향은 같은 정의인가? | 회사 고유 효과와 일회성/업황을 구분할 근거가 없으면 미확인 |
| 2 | 유조선(DHT 대표, FRO/INSW 비교) | 이미 확보한 계약·운임·가동일수로 확인되는 이익과 향후 운임 가정은 무엇인가? 공통 테마에서 회사별 차이는 무엇인가? | 분기 실적과 다른 연도의 예상치를 단순 연율화해야만 기대차가 나오면 보류 |
| 3 | VSEC | EPS 상향 중 회계 정의·인수·희석·실제 사업 성장의 영향을 구분할 수 있는가? | 이전 예상치의 정의를 확인 못 하면 EPS 상향의 비교 가능성 미확인. 사업 성장 자체와 별도 판정 |

각 주제는 저장 원문부터 읽고 결정에 필요한 추가 원문 최대3개를 먼저 선정한다. 관련 없는 자료를 끝없이 늘리지 않는다. 자료3개가 충분한 검증을 뜻하지는 않는다. 여전히 결정할 수 없으면 보류 사유와 해소할 단 하나의 다음 확인을 쓴다. 추후 새 근거가 있을 때 다시 연다.

각 결과는 다음 항목을 갖춘 1쪽 안팎의 요약과 근거표로 작성한다.

- 무엇으로 돈을 버는 회사인지, 이익 변화의 원인이 무엇인지 쉬운 한국어로 설명한다.
- 회사 사실/가이던스/시장 예상/연구 해석을 분리하고 원문 URL·문서ID·인용 위치·발표일·관측일·대상 기간을 붙인다.
- 예상치 비교는 기업·기간·출처·통화·단위·회계기준을 대조한다. 불명확하면 수치 비교를 확정하지 않는다. 과거 관측을 새로 만들어 넣지 않는다.
- 회사 규모 대비 변화, 지속 근거, 시장 예상과의 차이 각각을 확인/해석/미확인으로 표시한다. 주가 하락·낮은PER·EPS 상향 자체로 시장 미반영을 증명하지 않는다.
- 가장 강한 반대 근거1개, 틀렸다고 볼 조건, 다음 확인 자료/시점을 기록한다. 기업 발표를 독립적인 반증 근거로 둔갑시키지 않는다.
- 최종 판정: 추적 검토 가치 있음 / 특정 자료 대기 / 현재 가설 기각. 연구 판정이며 운영 카드의 승인·추적 상태를 자동 변경하지 않는다.

출력: `docs/u_candidate_decisions_2026-10-11.md`. 완료 기준은 세 주제 모두 판정·근거·한계·다음 행동을 갖추는 것이다. 추천3개를 채우는 것이 아니다. 실제 추천 승인은 기존 근거 검토 절차, 추적 등록은 사용자 선택을 따른다.

## U2 — 새 후보를 함께 봐 발굴의 폭 유지

U1 첫 판정표 뒤, 같은 주기 안에 최신 유효 스크린/저장 신호에서 기존8개 이외 최대5개를 짧게 비교한다. 신규 자료가 없으면 없다고 보고하고 과거 후보를 신규로 꾸미지 않는다. 기존 에너지 노출과 다른 이익 원인을 우선 살피되 업종별 할당이나 초대형 일괄 제외는 하지 않는다.

선정은 기존 시스템 순위에서 시작하고, 이익 변화의 크기·원문 사업 원인·지속 근거·기대차 순으로 살핀다. 스크린 순위와 연구 판단을 분리한다. 모집단·선정/제외 이유·최초 관측일을 남겨 결과가 좋은 것만 사후 선택하지 않는다. 숫자의 비교 불가와 접근 실패도 남긴다.

출력: 같은 판정 문서의 별도 신규 후보표. 기존3개에 비해 더 조사할 가치가 있는지 결정한다. 좋아 보이는 후보가 없어도 완료다. 여러 기업의 같은 원인은 하나의 연구 주제로 묶되 기업별 근거와 신호 원장은 보존한다.

## U3 — 연구를 막은 문제 하나만 개선 후보로 선정

입력: U1/U2에서 실제 판단을 막은 사례. 예상 개선 후보는 EPS 정의 변경 표시, 원문과 이익 원인의 연결, 초안 처리 순서, 공통 원인 묶음이다. 지금 어떤 기능을 만들지 미리 확정하지 않는다.

`docs/u_discovery_review_2026-10-11.md`에 다음 표를 만든다: 문제 사례 → 현재 결과 → 기대하는 사용자 결과 → 자료 부족인지 코드 결함인지 → 가장 작은 수정 → 검증 방법. 빈도뿐 아니라 판단을 잘못 이끄는 정도로 우선순위를 정한다. 서로 다른 후보2개에서 반복되거나 한 후보에서 중대한 오판을 유발한 증거가 있는 문제 중 최대1개를 고른다. 근거가 없으면 이번 주기 코드 변경0건으로 끝낸다.

선정한 개선안은 수정 파일·입출력 예시·실패 처리·예산 영향·완료 기준까지 적어 Codex 검토 대상으로 넘긴다. 현행 소스를 읽고 실제 파일명을 정하며 추측으로 함수·스키마를 지정하지 않는다. 이 계획만으로 연구 원장 마이그레이션·알림 정책 변경·모델 교체를 함께 진행하지 않는다.

구현 시에는 문제를 드러내는 대표 실패 사례와 수정 후 기대 결과를 비교하고 관련 회귀시험을 실행한다. 연구 문서만 작성할 때 전체 테스트를 반복할 필요는 없다. 새 발굴 조건의 성과 평가는 등록 이후 관측으로 시작한다.

## 운영 유지와 보류 작업

S0는 구현 인수 상태다. 기존 일간과 recover 로그로 정상 처리/자료 품질/알림 적격·전송/대기 증감을 짧게 확인한다. S0 실제503 동작이 발생하지 않으면 미관측으로 남기고 연구를 계속한다. 점검은 작업일당1회 기존 결과 읽기를 기본으로 하며 별도 반복 감시·수동 전체 실행·시험 발송을 만들지 않는다.

즉시 수정할 조건은 원장 손상, 잘못된 기업·수치로 판단/발송, 중복 발송, 검증된 적격 위험 알림의 코드상 누락이다. 단순히 시험을 더 늘릴 수 있다는 이유로 인수를 다시 열지 않는다. 모델 대기·품질partial·적격0건은 각각 이유와 영향으로 판단하며 그 자체를 장애로 취급하지 않는다.

429는 기존 진단 기록과 T의 설계 결정을 보존한다. 실제 한도/프로젝트 범위가 확인되고, 정상 운영 모델 작업이 연속2회 일간에서 한도로 멈추거나 서버의 일일 한도와 내부 계수 충돌이 직접 확인되면 필요한 예산/차단 수정만 우선 처리한다. 그전에는 예산 날짜 이중 관리 구현을 주작업으로 올리지 않는다. 연구의 선행 조건도 아니다.

thinking 비교는 이번 주기의 필수 산출물에서 제외한다. 운영 예산을 빼앗지 않으며 실제 한도와 평가 여유가 확인된 후 별도 진행한다. 새 모델·새 화면·새 에이전트·대규모 출처 확대·예약 시각 이동은 이번 범위 밖이다. 기존 추적 종목의 정기 갱신과 위험 신호 처리는 계속한다.

## 1주기 평가와 다음 결정

`docs/u_discovery_review_2026-10-11.md` 끝에 모집단과 함께 다음 수치를 기록한다: 검토 주제/기업 수, 원인 설명을 원문으로 확인한 수, 예상치 비교 가능한 수, 지속 근거와 반증 조건을 갖춘 수, 기대차를 확인/미확인한 수, 판정별 수. 서로 다른 분모를 섞지 않는다. 사전 수익률 성과는 아직 평가 기간이 찬 표본에만 기존 정의로 계산한다.

첫 주기는 기준선 확보다. 작은 표본에 임의 적중률 목표를 붙이지 않는다. 판단 결과에 따라 다음 방향을 고른다.

- 근거 있는 후보가 남으면 사용자에게 추적 검토 이유를 제시하고, 이후 신규 발굴을 이어간다.
- 대부분 정의/주체/원문 문제로 판정 불가면 그 자료 품질 문제1개를 먼저 보완한다.
- 자료는 맞지만 이익 원인·지속성·기대차가 빈약하면 후보 선정 기준을 조정한다. 운영 안정화로 해결될 문제라고 보지 않는다.

## 인수인계와 이번 작업 범위

Claude는 첫 인수인계의 첫머리에 후보 판정과 원문 근거를 제시한다. 운영 기록은 짧은 별도 항목으로 둔다. 결과·자료 부족·다음 행동과 수정 파일을 STATUS에 기록한다. 동시에 같은 체크아웃에 쓰지 않는다. 외부 발송·자동 추적 등록은 이 계획에 포함하지 않는다.

이번 Codex 작업은 방향·계획 문서와 STATUS 갱신이다. 기존 미커밋 scripts/extract.py와 tests/test_q2_overload.py를 보존했다. 후보 연구 실행, 운영 코드 변경·시험·모델 호출·발송·push는 하지 않았다.
