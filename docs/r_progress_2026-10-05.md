### R1 실패 알림 재전송 조건 (de157da, material-update-v3)

- **조건 재검증**: failed/released 이벤트는 예약 당시의 조건(`parts`)이 **모두** 현재도 유효할 때만 같은 ID로 다시 보낸다.
- **취소**: 다음 경우에는 그 이벤트를 `cancelled`로 바꾼다. 이전 시도 기록은 보존하고, 사유·빠진 조건·현재 관측을 `cancellations`에 남긴다.
  - B 소멸
  - A 검증 탈락
  - 비교 키 변경
  - 추적 전환
- `cancelled`는 재시도 대상이 아니다.
- **남은 조건의 새 이벤트**: 취소가 원장에 저장된 **다음 실행**에서만 만든다. 같은 실행에서는 `replacement_after_cancel`로 대기한다.
  - `supersedes`로 원래 이벤트와 연결한다.
  - 사건 날짜는 바꾸지 않는다.
  - 기존 한도·간격·예약 절차를 그대로 따른다.
- reserved/uncertain은 겹치는 조건을 계속 잠근다. 조건이 바뀌어도 대체 이벤트를 만들지 않는다.
- **같은 본문**: 재시도할 때는 처음 예약한 본문 그대로 보낸다(`payload_text`와 해시 저장). 오늘 카드의 회사명이나 주의 문구가 바뀌어도 전송문은 같다.
- 품질 부족이면 취소하지 않고 보류한다(기존 `quality` 판정).
- v3 첫 기록 전에 원장을 한 번 백업한다(`candidate_alerts.pre_material-update-v3.json`).
- PBF 대기 첫 관측, A-only 뒤 B 기준 유지(Q1)는 그대로다.
- 시험 5개 추가
  - A+B 실패 후 B 소멸 → 옛 알림 전송 0, 다음 실행에서 A-only 1건(supersedes), 이후 멱등
  - A 탈락 후 B만 남음 → 옛 복합 알림 0, B-only 1건
  - 조건 유지 → 같은 ID·같은 본문·같은 해시, 바뀐 카드 이름이 전송문에 없음
  - 비교 키 변경 → 취소
  - uncertain 복합 이벤트 → 대체 없음
- 재현 `failed_AB_retries_after_B_lapses` 해결. 전체 559개 통과.

- **수정**
  - `queue.days[KST 날짜].retries`에 그날 실제 재시도 요청 수를 저장한다.
  - 저장 시점은 요청 수와 함께, 보내기 직전이다. 결과와 관계없이 소비로 남고 되돌리지 않는다.
  - 요청을 보내기 전에 시간 한도로 멈춘 종목은 세지 않는다.
  - 각 호출에는 남은 몫(`retries_per_day - retries`)만 배정한다. SPY와 미시도 종목은 재시도 몫에 넣지 않는다.
  - 받을 종목이 없으면 SPY도 요청하지 않는다(`retry_share_used`/`nothing_due`).
- **이전 형식의 날짜 기록**: `retries` 필드가 없는 날짜는 요청이 0건이면 0에서 시작한다. 요청이 있었다면 재시도 사용량을 증명할 수 없으므로 그날만 몫을 모두 쓴 것으로 본다.
- **보고**: 이번 실행의 요청·재시도 수와 그날 누적(`day_requests`, `day_retries`)을 구분한다.
