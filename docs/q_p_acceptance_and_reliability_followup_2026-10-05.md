- B 포함 이벤트가 `sent`이면 그 예약 시 고정한 current EPS로 기준을 옮긴다. A+B는 한 이벤트/한 메시지이고 B 기준을 한 번 갱신한다. 기간/통화/기준 변경은 기존대로 알림 없이 rebase와 사유를 기록한다.
- `failed`는 기존 사건으로 재시도, `reserved/uncertain`은 자동 중복 생성·발송을 막는다. uncertain을 확인된 전달로 간주해 B 측정 기준을 바꾸지 않고 미확정 사건을 잠근다. 단순 날짜/조건 추가 때문에 실패·불확실 사건에 새 ID를 부여하지 않는다.
- B가 성립해도 기업별14일·하루1·공유3 한도는 유지한다. A 직후 B 확인이 됐다고 즉시 재발송하지 않는다. 대기 중 조건 소멸/추적 전환/비교 키 변경은 취소 기록을 남긴다.
- 이전 원장 백업·호환 읽기·멱등 마이그레이션을 제공한다. 10/5 PBF 첫 관측은 유지한다. A-only 과거 영수증이 있다면 확인 가능한 최초 기준/마지막 B 영수증으로 복원하고, 근거가 없으면 사유를 남겨 기준만 재설정한다. 소급 이벤트를 발송하지 않는다.
- 시험: 1.00→1.30 첫날 A-only→1.31 둘째날은 B +31% 확인을 유지하되 간격으로 미발송, A+B 한 번, B sent 뒤 새 기준, 실패/불확실 중복 금지, AEHR 0 변화 거부, PBF 대기 보존.

## 5. Q2 — 503 실패 후 예산을 보존하며 재개

수정: `scripts/common.py`, `extract.py`, `candidate_context.py`, `daily_run_state.py`, `config/research_policy.json`, 공용 모델/일간 계획 시험. 새 의존성은 필요 없다.

[Google 공식 오류 대응](https://ai.google.dev/gemini-api/docs/troubleshooting#retry-strategy)은 일시적 오류에 지수 대기·jitter·최대 재시도를 권한다. 아래 시간과 횟수는 이 프로젝트의 적은 일일 예산에 맞춘 운영 시작값이며 제공자의 보장값이 아니다.

- 공용 모델 상태에 모델별 연속503·재개시각·대기 단계·마지막 요청 결과를 기록한다. 연속503 **2회**면 해당 모델을 **30분** 쉬고, 재개 탐색 1회도503이면 **60→120→최대360분**으로 늘린다. 매 대기에 0~30초 jitter를 저장해 반복 계산으로 시각이 바뀌지 않게 한다. 성공 응답은 연속503과 대기 단계를 초기화한다.
- 모든 컴포넌트가 같은 모델의 대기를 존중한다. 429는 기존 Retry-After/다음 KST 날짜 규칙을 유지하며 503 상태 갱신이 429 차단을 단축하지 않는다. 실패 HTTP 요청도 예산에서 차감한다.
- 초안은 같은 기업을 한 실행에서 즉시 반복 요청하지 않는다. 503 실패 기업의 `draft_next_at`은 24시간 고정 대신 대기 정책을 따른다. 400/검증 실패는 과부하로 분류하지 않는다. 네트워크/다른5xx 기존 최대1회 재시도에도 공용 예산·deadline을 적용한다.
- 모델 총20, extract11/cards3/context6 한도는 유지한다. 재시도도 해당 몫 안에서만 가능하다. 남은 예산이0이면 그날 추가 시도하지 않는다. 따라서 이미6회를 쓴 10/5에 추가3회를 보태는 지시가 아니다.
- **재개 경로까지 구현한다.** 현재 context는 `partial_top_up=False`여서 next_at만 앞당겨도 같은 날 auto가 실행하지 않는다. 다음 기존 예약 auto에서 대기 만료·미처리 현재 후보·남은 예산이 있을 때만 초안 재개를 계획한다. 별도 고빈도 타이머나 전체 daily 재실행을 만들지 않는다.
- 재개는 보관 문서/유효 입력을 사용한다. 그 때문에 screen·SEC 수집·이미 성공한 초안을 반복하지 않는다. context 결과가 바뀐 경우 cards/views와 기존 의존 단계가 갱신되며 알림 한도·중복 방지는 그대로다. 오래됐거나 품질 held인 스크린에서는 재개하지 않는다.
- 실제 실패, 예산 소진, 제공자 대기, 미시도 상태와 재개 예정시각을 구분한다. 실패를 성공 자료로 세지 않는다.
- 시험: 가짜시계/가짜HTTP로 503연속2·대기 중0요청·재개1회·재실패 배수·성공 reset·429 우선·KST 자정·공용/개별 예산·deadline·재개 계획의 SEC0요청을 확인한다. 실서비스에 장애를 재현하지 않는다.

### Q3-B 범위·비용·보관

- 대상은 식별 가능한 전체 조건 통과 기업(현재127곳)이며, 초기 대기열은 현재 목록으로 고정한다. 현재 대표 카드/알림 경험44곳을 먼저, 나머지83곳을 최초 통과 순으로 처리한다. 이후 신규 진입이 기존 나머지 대기열을 계속 밀어내지 않게 FIFO로 추가한다. 44/83은 코드 상수가 아니다.
