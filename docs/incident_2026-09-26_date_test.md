## 원인

G2 초안 테스트가 "다음 날"만 2026-09-26으로 고정하고 첫 실행은 실제 날짜를 썼다. 실제 KST 날짜가 9/26이 되자 두 실행이 같은 예산 날짜를 공유해 기대값이 깨졌다. 운영 코드 결함이 아니라 테스트의 실제 날짜 의존이다. 다만 일간 작업이 테스트 통과를 전제로 하므로 수집·명령·알림이 모두 멈췄다.

## 영향

- 9/26 KST 일간 단계(수집·추출·EPS·가격·스크린·카드·알림 등)는 복구 run 1회로 22:35 KST에 실행됐다. 그 이전 시각의 관측은 없다. 소급 관측을 만들지 않는다.
- 명령 확인은 실패 run들에서 처리되지 않았고, 복구 run의 명령 단계에서 처리됐다.
- 원장 손상·중복 발송은 없다(실패는 테스트 단계, 상태 저장 전).
