# v7 운영 인수 판정과 L 후속 구현 지시

작성: Codex, 2026-10-04 KST. 기준 HEAD `6409b5c`. 다음 구현 담당자는 이 문서와 STATUS.md를 읽는다.

사용자 요청에 따라 판정·설계·구현 지시를 작성했다. **직접 수정한 코드는 goodwill 오탐 한 가지이며, 나머지 L0~L4는 구현 지시다. CLBK 운영 노출을 이번 작업에서 해소한 것은 아니다.**

Codex가 로컬에서 직접 확인한 사항:

## 2. 실행 순서와 버전

1. **L0 긴급 격리**: 저장된 CLBK 오류의 현재 노출을 차단하고 출력물을 갱신한다. 다른 문장 수용 규칙은 바꾸지 않는다. 카드 버전 `cards-v5`.
2. **L1 정확성**: 변화량/수준값 검사 + 저장 v7 초안의 읽기 시 재검증. 이번 goodwill 패치도 이 릴리스에 포함. 검증기 `context-check-v8`, 일간 단계 `context-v8`.
3. **L2 과잉 거부 보완**: AXTI·drivers·adjusted·상향 활용형. L1의 오류 차단 시험이 먼저 통과해야 한다.
4. **L3 표시 선택**: 핵심 사실·현재 기간·실제 한계 우선, `cards-v6`.
5. **L4 오프라인 평가와 배포 증거**: 단계별 변화와 신규 수용을 전부 대조하고, 다음 정상 운영에서 확인한다.

L1·L2를 하나의 미배포 변경 묶음으로 완료하면 v8을 함께 사용한다. L1을 먼저 배포했다면 L2는 `context-check-v9`/`context-v9`로 올려 같은 버전명에 서로 다른 규칙을 배포하지 않는다. L0를 먼저 배포하면 cards-v5, 이후 L3는 cards-v6로 구분한다.

**현재 goodwill 변경은 미배포 준비 패치다.** PARSER_VERSION과 일간 버전은 아직 v7이며, 이 상태로 단독 배포하지 않는다. L0 긴급 배포 커밋에는 이 검증기 변경을 포함하지 않고, L1에서 v8 변경·검증과 함께 배포한다. 버전만 먼저 v8로 올려 변화량 검사까지 끝난 것처럼 보이게 하지 않는다.

## 3. L0 — CLBK 현재 노출 격리

목적: 새 모델 응답이나 v8 완성을 기다리지 않고 확인된 오류를 현재 사용 경로에서 제외한다.

수정 파일: 새 `config/context_quarantine.json`, `config/schema.json`, `scripts/candidates.py`, 필요한 현재 카드 소비 경로(`scripts/telegram_cmd.py`, `scripts/candidate_alerts.py`), `scripts/daily_run_state.py`, `tests/test_candidates.py` 및 해당 소비 경로 테스트. 공통 진입점은 `context_inputs()`, `load_index()`, `card_lines()`, `render_html()`의 내장 candidate JSON, `import_context()`, `approve()`다.

등록 형식은 `schema_version: 1`, `contexts: {CTX-ID: entry}`로 한다. entry의 필수 값:

- `candidate_id: CAN-E763F753A2D7609F`
- `reason: delta_reported_as_level`
- `source_ref: DOC-AC201A9BE0E4E848#p19`
- `decided_at`: 실제 조치 시각(UTC ISO), `decided_by: Codex specification / implementation actor`
- `note`: 순이자이익 증가분을 수준값으로 표시해 원문 초안 재검증 전 사용 중지

적용 규칙:

- **정확한 CTX ID 한 개 전체**를 격리한다. 티커 전체 또는 다른 정상 CTX까지 차단하지 않는다. 원래 CTX·감사·공시·후보 버전·관측 파일은 삭제/수정하지 않는다. `$62.9M`으로 치환하지 않는다(다른 인용·검증이 필요함).
- `context_inputs()`뿐 아니라 기존 index를 읽는 현재 카드, Markdown/HTML/내장 JSON, `/candidate`·`/screen` 본문 작성, import-context와 approve의 현재 입력 재계산에도 동일한 격리 판정을 적용한다. 서로 다른 차단 목록을 만들지 않는다. 출력용 복사본에서 처리하고 원래 저장 객체를 변경하지 않는다.
- 화면에는 `공식 발표 초안 재검증 중 — 변화량과 실제 값의 혼동이 확인되어 해당 초안 표시를 중지했습니다.`라고 표시한다. EPS 스크린 결과와 회사 식별, 다른 사람이 작성한 독립 근거는 유지한다. 이를 SEC 접근 실패나 모델 실패로 기록하지 않는다.
- `imported_from`이 이 CTX인 사람 근거가 있으면 해당 가져온 근거도 현재 사용에서 보류하고 재검토를 표시한다. 기존 승인 이벤트를 삭제/수정하거나 새 승인으로 이월하지 않는다. 독립적으로 작성된 다른 사람 근거까지 연쇄 무효화하지 않는다.
- 과거 관측을 열면 오류 확인 사실과 당시 기록임을 표시하고, 알려진 오류 초안을 현재 검증된 근거처럼 다시 사용하지 못하게 한다. 과거 저장 파일은 불변이다.
- 설정 파일 누락/손상은 빈 격리 목록으로 바꾸지 않는다. 현재 화면의 초안 표시·가져오기·승인 경로를 실패 처리하고 이유를 남긴다. 정상 빈 목록은 명시적인 유효 파일로만 허용한다.
- 새로운 CTX는 별도 검증 후 사용할 수 있다. 격리한 ID는 남겨 과거 index에서 재등장하지 못하게 한다.

완료 기준: CLBK 오류가 현재 세 출력(Markdown·HTML 내장 JSON·명령 응답 본문)에서 없어지고 경고가 보인다. 저장된 원본과 과거 관측 해시는 같아야 한다. 관련 CTX 가져오기/승인이 거절되고 다른 후보는 종전대로 동작해야 한다. 새 화면·카드 버전/관측은 실제 재생성 시각·출처를 기록하며 이전 날짜에 있었던 관측으로 소급하지 않는다. 이미 다운로드한 옛 HTML이나 과거 발송 메시지가 고쳐졌다고 보고하지 않는다.

검증은 격리된 임시 데이터 복사본과 실제 전송 없는 본문 생성으로 수행한다. 실운영 쓰기는 CI 단일 작성자에서 수행하고 로컬 원장과 동시에 쓰지 않는다. 새 모델/SEC 요청·Telegram 발송·추적 등록은 필요 없다.

## 4. L1 — 변화량/수준값 검사와 기존 초안 처리

수정 파일: `scripts/candidate_context.py`, `scripts/candidates.py`, `scripts/daily_run_state.py`, `config/schema.json`(새 메타데이터 정의), `tests/test_h_followup.py` 또는 별도 `tests/test_l_followup.py`, `tests/test_candidates.py`, 작은 실제 원문 fixture.

### 4.1 숫자 역할 검사

검사 대상은 claims와 limitations의 **모든 figures**다. 숫자 원문 일치·지표·주체·기간·GAAP 검사를 대체하지 않는다. 인용과 해당 수치 구간에서 다음 역할을 판별한다: `level`, `delta`, `effect`, `ambiguous`. 모델이 붙인 역할이나 한국어 note를 정답으로 신뢰하지 않는다.

- `increase/decrease ... by <금액>`, `increase/decrease of <금액>`, `<금액> increase/decrease in <지표>`, `raised/lowered ... by`, `increased ... by a net, after-tax benefit of ...`처럼 수치에 직접 붙은 변화 문법을 검사한다. approximately/net/after-tax 등 제한된 삽입 표현을 지원한다.
- `increased **to** <값>`, `was <값>`, `from <전년값> to <당기값>`의 목표 값은 변화량이 아니다. 문장 어딘가에 increase/by가 있다는 이유로 전체 숫자를 변화량으로 만들지 않는다. `reported by`, `by the company`도 변화 문법이 아니다.
- 각 수치를 지표·절에 묶는다. 같은 수치 문자열이 여러 번 나와 역할/지표가 달라지면 첫 `find()` 결과로 정하지 않고 `figure_role_ambiguous`로 거부한다. 소수점·괄호 음수·범위의 양 끝을 손상시키지 않는다.
- v8 첫 구현은 **변화량을 수준값처럼 공급한 주장 전체를 `delta_presented_as_level`로 거부**한다. CLBK `$9.2M`, PBF 순이익 `$159.8M`/주당 `$1.32`, DAN 전망 `$225M`/`$25M`, SUNC 증가분·수준값 혼합이 이 대상이다. 혼합 figures에서 틀린 값만 몰래 삭제해 새 주장을 만들지 않는다.
- 단, figures 자체가 원문 그대로 `decreased oil revenues by $28.5 million`처럼 방향과 변화 관계를 완결해 보존한 경우는 유지할 수 있다. 출력에도 코드가 `변화량(감소)`를 붙여 수준값 머리말과 혼동되지 않게 한다. note에만 '증가했다'가 있는 것은 이 예외가 아니다. 증감 폭을 받아들이려면 방향·기준이 해당 지표에 명확해야 한다.
- 손상차손/세금 효과/처분손익이 순손실·순이익에 영향을 주는 문장에서, **효과 금액을 순손실/순이익 수준으로 붙이면 `effect_presented_as_level`로 거부**한다. 반면 metric 자체가 goodwill impairment loss 등 해당 비용이면 그 비용의 수준값일 수 있다. `benefit of`라는 문자열만으로 모든 tax benefit 지표를 차단하지 않는다. 이 규칙은 goodwill 오탐 해제 뒤의 RPAY 원응답도 다시 점검한다.
- `5% 증가`·`25 basis points 상승`과 `매출총이익률 45%`·`매출의 18–22%`를 구분한다. 비율 지표의 분모를 성장률로 읽거나 `%`를 전부 변화량으로 분류하지 않는다. 이 범위에서 명확히 판별할 수 없는 혼합 표현은 보류한다.
- 확정할 수 없는 관계는 거부 사유와 원문을 남긴다. 다른 문단의 수준값을 가져오거나 계산해 자동 교정하지 않는다. 원문이 지원하지 않는 note의 인과 설명까지 숫자 검사로 검증했다고 간주하지 않는다.

필수 시험:

1. CLBK p19의 `$9.2M` 수준값 거부, p20의 `$62.9M` 당기 수준값 허용, 전년 `$53.7M`의 당기 혼입 거부.
2. DAN 실제 문장의 sales `$225M`와 adjusted EBITDA `$25M` 각각 거부. L2의 adjusted·상향 활용형 보완을 켜도 동일.
3. PBF 특별항목의 순이익/주당순이익 효과를 수준값으로 거부, TXO 완결된 감소분 표현은 명시적 변화량 표시로 유지.
4. 한 문장에 수준값과 변화량이 공존하면 수준값만 선택한 주장은 허용, 두 역할을 수준값으로 섞은 주장은 거부.
5. `to`·`from ... to`·`reported by` 음성 대조, 감소/음수/범위/근삿값, 동일 금액 두 번의 모호성.
6. 영업권 손상 '영향 금액'과 실제 순손실을 교환하면 거부, 손상차손 자체 지표는 허용 가능. 원문의 주체/기간 검사도 유지.
7. `%` 성장·basis points 변화·이익률 수준·매출 대비 비율을 구분. 기존 'Revenue rose 5% to $40 million' 시험도 숫자의 역할에 맞는 출력/거부를 검증하도록 갱신한다. 기존 잘못된 표시를 보존하려고 검사를 약화하지 않는다.

### 4.2 저장된 v7 초안의 처리

모델 호출은 하루 6개이므로 v8 전환 때 모든 기존 근거를 새 추론으로만 복구하려 하지 않는다. `context_inputs()`에 순수 함수 형태의 **저장 초안 재검증 뷰**를 추가한다.

- v7의 수용 claims/limitations만 저장 공시 블록으로 v8에 다시 넣는다. `source_blocks`와 문서 ID·원문·발행사 식별·대상 회계연도를 확인하고 동일 검사 함수를 사용한다. issuer 정보가 없거나 충돌하면 추측하지 않는다.
- 잘린 rejected excerpt로 원응답의 metric/period/kind를 복원하지 않는다. v7에서 거부된 문장을 되살리는 평가는 전체 감사 응답이 있는 L4에서만 한다. 현재 뷰에서 accepted-only 재검증과 원응답 전체 재평가를 혼동하지 않는다.
- 원본 CTX·생성일·parser_version은 그대로 둔다. 뷰에 `source_parser_version`, `display_validator_version`, 원본 context_id, `validation_scope: accepted_only`, 원본 생성 시각을 표시한다. 오늘 재검증했다는 이유로 공시/모델 생성일을 오늘로 바꾸지 않는다.
- 새로 거부된 문장은 뷰에서 제외하고 context_status/core를 다시 계산한다. 텍스트는 검증 결과로 다시 조립한다. 문서 누락·검증 예외는 `재검증 불가`로 표시하고 기존 미검증 숫자를 fallback으로 노출하지 않는다.
- 명시적 지원 버전은 v7과 새 v8만이다. 이전에 제외하던 v4 등까지 무조건 허용하지 않는다. L0 격리는 재검증 결과보다 우선한다.
- 뷰 내용·규칙 버전은 카드 내용 해시에 포함하고, 매번 달라지는 조회 시각은 해시에서 제외한다. 같은 입력을 두 번 읽으면 버전·관측이 늘어나지 않는다. 기존 승인 이벤트는 유지하되 바뀐 후보 버전을 자동 승인하지 않는다.
- 현재 index·기존 index를 읽는 본문 경로·import-context·approve가 같은 재검증 뷰를 쓴다. 원문/모델 접근 실패 시에도 재검증을 통과한 마지막 근거와 원래 날짜만 유지한다.

시험: 저장 v7의 bare 변화량이 현재 출력에서 사라짐, 정상 수준값 보존, 공시 누락 시 차단, 다른 회계연도 미연결, 이전 CTX/승인/관측 파일 불변, 읽기 반복 시 동일 결과, 네트워크 0. 새 v8 모델 초안과 v7 재검증 뷰의 출처 표기를 구분한다.

## 5. 직접 수정한 goodwill 및 L2 과잉 거부 보완

### goodwill 패치

`scripts/candidate_context.py`에서 `will ` 부분 문자열을 FORWARD에서 분리하고 `has_forward_wording()`의 `\bwill\b`로 검사한다. fact 거부와 guidance 허용 양쪽에서 같은 함수를 쓴다. 나머지 전망어 어간의 의미·범위는 바꾸지 않았다.

`tests/test_h_followup.py`의 `ForwardWordingTest` 4개는 과거 goodwill 문장의 claim/limitation 허용, goodwill만 있는 guidance 거부, 실제 will(대문자/줄바꿈 포함)의 fact 거부와 guidance 허용, goodwill과 실제 will/expect가 함께 있을 때 전망 검사 유지다. **독립적인 합성 경계 사례이며 실제 RPAY 원응답 전체의 통과를 보장하는 시험은 아니다.**

현재 검증: 코드에서 추출한 전망어 목록/정규식을 Node로 확인한 7개 어휘 사례 통과, 양쪽 호출부 확인, `git diff --check` 통과. Python은 PATH에 없고 `py --list-paths`는 `No installed Pythons found`이며 사용자 Python 설치 경로는 현재 실행 계정에서 접근 거부였다. 따라서 **Python 단위/전체 테스트 및 CI는 미실행**이다. 다른 설치 경로에서 임의로 권한을 바꾸거나 전역 설정을 고치지 않았다.

### L2 세부 지시

같은 검증기·프롬프트 파일과 원문 fixture를 수정한다. 프로덕션 raw 응답과 원문은 보존한다.

- **AXTI**: `percent of revenue`의 revenue는 바로 붙은 비율의 분모인 경우만 지표 근접 검사에서 제외한다. 별도 매출 금액까지 제외하지 않는다. `was a net income of`의 반복 지표명은 동일 절·동일 주체·동일 GAAP 기준인 경우에만 앞 지표와 연결한다. 귀속/연결, GAAP/non-GAAP, 부문/회사 전체의 교환은 계속 거부한다. AXTI 순이익 2건·매출총이익률 1건 허용과 지표/주체/회계기준을 바꾼 음성 대조가 필수다.
- **drivers**: list[str] 형식 검사는 유지한다. 유효 enum만 원래 순서로 중복 제거해 남기고 모두 범위 밖이면 `["unknown"]`으로 둔다. 원래 태그와 정규화 이유를 감사/검증 경고에 보존한다. `customer_demand`를 임의로 volume 등으로 추론하지 않는다. direction 및 사실 본문 검사까지 느슨하게 하지 않는다.
- **gaap=adjusted**: 공백/대소문자를 정규화한 정확한 값 adjusted만 후보로 삼고, 해당 지표·수치의 `gaap_basis`가 non-GAAP일 때만 non-GAAP으로 정규화한다. 원문이 GAAP/unknown이면 계속 거부한다. 다른 지표의 adjusted 표기나 회사 전체 비GAAP 면책 문구를 근거로 삼지 않는다. 원값/정규화값을 보존한다.
- **상향 활용형**: 단어 경계를 갖춘 raise/raises/raised/raising, increase/increases/increased/increasing 및 이에 대응하는 하향 표현을 지원한다. 기존 상향·하향 동시 문장 안전장치를 없애지 않는다. URGN의 정확한 전망은 수용할 수 있지만 DAN 증가분은 L1에서 계속 차단되어야 한다.
- 프롬프트의 gaap 설명은 허용 enum을 명확히 해 `adjusted라고 적힌 지표도 출력 gaap은 non-GAAP`임을 설명한다. 실제 프롬프트 문구를 바꾸면 PROMPT_VERSION을 `context-ko-v4`로 올린다. 오프라인 재검증은 종전 v3 응답 그대로 수행하며, 새 프롬프트 효과를 입증했다고 보고하지 않는다. 추가 실호출 없이 다음 정상 실행에서 확인한다.

## 6. L3 — 카드와 한계의 표시 선택

수정: `scripts/candidates.py`의 공통 선택 함수/렌더, `scripts/daily_run_state.py`, 카드 시험. Markdown·HTML·명령 응답에 같은 선택 결과를 쓴다. 검증기 수용 배열·원본 순서를 고쳐 쓰지 않는다.

- 사실 최대 3개는 검증된 fact/guidance만 대상으로 한다. 정렬 키는 `(기간 등급, 이익 정보 등급, core 우선, 원래 순서)`이다.
- 기간 등급은 `현재/전망=0`, `미확인=1`, `명시적 과거 비교값=2`. 기준은 **해당 공시의 확인된 보고 기간**이며 스크린 EPS 대상 연도가 아니다. 명시된 날짜·연도/분기만 비교하고, 기간 파싱/문서 기준이 불명확하면 미확인으로 둔다. 'second quarter'에 연도를 만들어 넣지 않는다.
- 이익 정보 등급은 `특별항목 제외 조정 순이익·조정 EPS=0`, `순이익·EPS·영업이익=1`, `기타=2`. 해당 지표/조정 여부가 검증된 경우만 적용한다. 서로 다른 기간·GAAP/비GAAP·수치가 다른 문장을 중복으로 지우지 않는다.
- PBF는 당기 조정 순이익이 과거 비교값보다 먼저, AMCX는 기간 있는 핵심 가이던스가 기간 미확인 보조 사실보다 먼저 나와야 한다. 정렬에서 밀린 문장의 원문/전체 검토 접근은 남긴다. core 개수 증가가 실용성 개선의 증거는 아니다.
- 기간 unknown인 수치·가이던스는 제목에도 `기간 미확인`을 표시한다. TEAM을 인접한 4분기/연간 제목에 자동 귀속하지 않는다.
- 한계 최대 2개는 `특정 일회성 손익/손상/비반복 사건 > 특정 사업 위험/상쇄 요인 > 일반 면책` 순이다. 우선순위 판단은 검증된 quote에서 한다. 모델의 one_off 태그만으로 높이지 않는다.
- 비GAAP 면책은 `not ... substitute/alternative`, `not ... comparable`, `not ... in isolation`처럼 대체/비교 불가를 설명하는 일반 문구로 한정한다. 이를 BOILERPLATE에 광범위하게 넣어 원문 수집이나 검증에서 제거하지 않는다. 실제 조정 순이익·손상차손이 있는 혼합 문단은 계속 보존한다. 일반 면책만 있으면 `구체적인 일회성·반대 근거는 아직 확보하지 못했습니다`를 표시하고, 면책은 보조 설명으로 둔다.

완료 시험: PBF·AMCX 실제 사례, 한계 앞 2개가 면책이어도 뒤의 실제 경고가 선택됨, non-GAAP 순이익 본문이 면책으로 삭제되지 않음, unknown 기간 경고, 동일 입력의 안정적 순서/후보 버전, 세 출력의 선택 일치, 승인 자동 이월 없음.

## 7. 이번 범위에서의 보류 결정

- **머리글 기간 상속**: 보류. 후속 설계는 문서 파서가 heading→본문의 명시적 범위를 보존하고, 모델이 부모 heading ID를 참조하며, 원문에 복수 기간/비교 표가 있을 때 모호성을 거부하는 방식으로 한다. 임의로 앞 문단의 기간을 붙이지 않는다.
- **수치 뒤 기간·respectively**: 이번 L1/L2에 넣지 않는다. 정확히 N개 기간과 N개 수치의 순서 대응 및 동일 지표·주체를 입증하는 fixture가 있는 별도 수정으로 다룬다.
- **인과 설명**: CLBK의 note가 p19 밖 원인을 끌어온 것은 별도 미해결이다. 후속은 주장마다 원인 인용 블록을 추가하고 연결을 검증하는 설계다. 이번 숫자 역할 검사로 note까지 검증했다고 표현하지 않는다.
- **PSX JV**: subsidiary 분류 오류를 후속 데이터 의미 문제로 남긴다. JV를 자회사로 자동 변환하는 규칙은 추가하지 않는다. 현재 이름/원문이 정확하다는 점과 법적 귀속 분류가 틀렸다는 점을 구분한다.
- **503 대응**: L0~L3에는 재시도/예산 변경을 넣지 않는다. 즉시 재호출과 공용 429 차단 재사용도 하지 않는다. 후보별 실패/감사/요청 차감/마지막 검증 근거의 날짜 표시를 유지한다. 후속 회로 차단 설계는 '연속 503 2회 후 해당 실행의 남은 요청 미시도', 미시도 예산 차감 0, 별도 상태/다음 가능 시각, 같은 날 재개 조건까지 함께 정의해야 한다. 현재 8실패를 원문 근거 부족으로 집계하지 않는다.
- 실제 `/track` 시험 등록, 로컬 모델 재시작/추론, 새 SEC·Gemini 검증 요청은 이번 범위 밖이다.
