# 설계 문서: metric_log (지표/리비전 시계열) — 미구현

> 상태: **설계만.** 구현 담당: Codex. 이 문서만 보고 자족적으로 구현 가능하도록 작성했다.
> 기존 시스템 규약(`config/schema.json` 단일 진실원천, UTF-8-SIG, 표준 라이브러리만, 테이블 유형 master/log/tracked)을 그대로 따른다.

## 1. 목적
EPS 컨센서스·가이던스 같은 선행지표의 **변화(Δ)**를 시계열로 기록해, 단계 루브릭
(상향 개시 → 연속 → 확대 → 둔화)을 숫자로 판정한다. 헤드라인 검색(후행)을 대체한다.

## 2. 핵심 원칙 (왜 이렇게 설계했나)
- **전 시장을 미리 쌓지 않는다.** 기록 대상은 ①정식 아이디어/병목 후보 + ②**관찰 후보**(아직 아이디어 아님, 상향을 목격해서 일단 적어두는 것)까지다. 이 ②가 **발굴 퍼널**이다.
- 평소엔 비어 있다가, **상향/하향/가이던스 변경을 관찰할 때만 한 줄** 추가하는 **이벤트형**이다. 관찰 후보는 **가볍게**(종목/지표/방향/출처/날짜만) 툭 적는다.
- **반복 상향이 쌓인 관찰 후보 = 발굴 신호** → `bottleneck_log` / `investment_review_log` 로 **승격**한다.
- 각 줄에 **이전값 → 현재값**을 함께 담아, 긴 과거 데이터 없이도 한 줄이 Δ를 담게 한다.
  (정밀 연속 리비전 히스토리는 유료라 개인이 소급 불가 → 이 방식으로 baseline 문제를 푼다.)
- **같은 FY끼리만 비교한다.** 지표명에 연도를 박는다(예: `2027F EPS`). 지표명이 다르면 다른 시계열.

## 3. 테이블 정의 — `data/processed/metric_log.csv` (type: log, append)
`config/schema.json` 의 `tables` 에 추가:
```json
"metric_log": {
  "type": "log",
  "key": "metric_id",
  "id_prefix": "MET",
  "columns": ["metric_id", "날짜", "종목/업종", "sector_id", "지표명", "방향", "이전값", "현재값", "변화율", "출처", "메모"]
}
```
`config/schema.json` 의 `enums` 에 추가:
```json
"방향": ["상향", "하향", "유지"]
```

## 4. `add_entry.py` 동작 (기존 log 처리 + 약간 보강)
- 기본은 기존 log 타입 그대로: `metric_id` 자동 부여 후 append (추가 코드 거의 불필요).
- 보강(권장, 선택 구현):
  1. `이전값` 미입력 시 → 같은 `(종목/업종, 지표명)` 의 **직전 줄 `현재값`**을 자동으로 `이전값`에 채움.
  2. `변화율` 미입력 + `이전값`·`현재값`이 숫자면 → `(현재-이전)/|이전|*100` 자동 계산(소수 1자리, % 문자열).
  3. `방향` 미입력 시 → 변화율 부호로 자동(`>0` 상향 / `<0` 하향 / `=0` 유지).
- enum 검증(`방향`)은 기존 `validate_enums` 가 자동 처리.

## 5. `gen_report.py` 추가 — `metric` 뷰 + 발굴 보드
- **발굴 보드** — `python scripts/gen_report.py metric` (인자 없음):
  모든 `(종목, 지표명)` 을 **연속 상향 횟수 내림차순**으로 정렬해 "지금 계속 상향되는 것들"을 한눈에 보여준다.
  기본은 **연속 상향 ≥ 2** 만 노출(임계치 인자로 조정 가능, 예 `--min 3`). 이게 발굴 진입점이다.
  컬럼: `종목/업종 | 지표명 | 연속 상향 횟수 | 최근 변화율 | 최근 날짜 | 출처`.
- **개별 상세** — `python scripts/gen_report.py metric "메모리 반도체"`:
  `(종목, 지표명)` 별로 **최신 현재값 · 연속 상향 횟수 · 최근 변화율 · 최근 날짜**를 표로 출력.
- **연속 상향 횟수 계산**: 해당 `(종목, 지표명)` 행을 날짜 오름차순 정렬 후, 가장 최근부터 거꾸로
  `방향 == "상향"` 이 끊기기 전까지 센다.
- board 뷰 연동(선택): 각 아이디어 행에 핵심 지표의 `연속 상향 N회 / 최근 Δ%` 를 덧붙인다.

## 6. 운영 절차 (발굴 = 외부, 추적 = 이 테이블)
- **발굴(무엇이 상향됐나)** 은 직접 쌓는 게 아니라 외부 스크린에서 가져온다. 점검 주기는 **주 1회 + 실적 시즌/주요 리포트 직후**:
  - **네이버 금융** — 컨센서스/추정실적 변화
  - **증권사 리포트, 특히 해외 IB** — 글로벌 커버리지 종목의 목표주가·추정치 상향
  - **한경 컨센서스** — 추정치 상향 리스트
- 관찰한 변경을 `metric_log` 에 한 줄 입력한다. **정식 아이디어가 아니어도** 상향을 보면 관찰 후보로 가볍게 적는다(= 발굴 퍼널). 이미 아이디어인 경우 해당 아이디어의 `최근 점검일` 도 함께 갱신한다.
- 주기적으로 `gen_report.py metric`(발굴 보드)을 보고, 연속 상향이 쌓인 관찰 후보를 정식 아이디어/병목 후보로 **승격**한다.

## 7. 한계 (정직하게)
- 점검 시점들 사이의 변화만 포착 → **연속성은 근사치**. 정밀 연속 리비전은 유료(FnGuide/Quantiwise).
- 무료 소스 스크래핑은 약관·구조 변경 리스크 → **처음엔 수동 입력**. 자동화는 그 다음 단계.

## 8. 예시 입력 — `examples/metric_log_example.json`
```json
{
  "target_table": "metric_log",
  "data": {
    "종목/업종": "메모리 반도체",
    "sector_id": "SEC-0001",
    "지표명": "2027F EPS",
    "방향": "상향",
    "이전값": "12000",
    "현재값": "13500",
    "출처": "해외 IB 리포트 / 네이버 컨센서스",
    "메모": "HBM 믹스 상향 반영"
  }
}
```

## 9. 완료 기준 (acceptance)
- `python scripts/add_entry.py examples/metric_log_example.json` → `metric_log.csv` 생성(UTF-8-SIG) + 1행.
- 같은 종목·지표로 한 줄 더 추가 시 `이전값` 자동 연결 + `변화율` 자동 계산.
- `python scripts/gen_report.py metric "메모리 반도체"` → 연속 상향 횟수/최근 변화율 표 출력.
- `python scripts/gen_report.py metric` (인자 없음) → 연속 상향 ≥ 2 인 (종목,지표)를 횟수순으로 출력(발굴 보드).
- `잘못된 방향` 값 입력 시 enum 검증으로 거부.
