# H 인수 판정과 남은 작업 — Codex, 2026-09-26

직접 확인한 증거:

- daily_runs 9/26: collect/extract/eps/notify/quarterly/screen/prices/context/cards/alerts/baseline/returns/views 13단계 execution_status=success. screen/context quality=complete, 나머지 unknown. 모든 데이터 품질이 완전하다는 뜻은 아니다.
- context_state: 원문 success 10, queued 20; SEC 요청 30, 조사 기업 10.
- 초안 상태: insufficient_earnings_context 1, no_supported_claims 4, failed 1, deferred_budget 4. 모델 예산: extract 5, cards 1, candidate_context 6.
- 알림 원장의 sent/message_id 137 유지.
- v3의 원문 연속 구절·지표/기간 연결 검사와 실제 출력 fixture 확인. 이 변경은 수치 자유 환산을 허용하는 것이 아니라 원문 범위/산업 단위에 대한 과도한 거부를 줄인다.

GitHub run 상세 로그·Telegram 화면, 미래 날짜 환경 전체 실행, 변이 시험은 이번에 다시 조회/실행하지 않았다. 해당 내용은 Claude 인수인계 증거와 구분한다. 다음 실행 날짜도 성공이 확정된 일정으로 표현하지 않는다.

## 2. I1 — 날짜 장애 재발 방지

대상 `.github/workflows/tests.yml`, tests의 시간 fixture/실행 보조 스크립트, 장애 기록 문서. 이번 사고는 운영 코드가 아니라 테스트의 실제 날짜 의존이 정상 파이프라인까지 막은 것이다. 일일 운영의 테스트 게이트를 즉석으로 제거하거나 실패를 무시하는 방식으로 해결하지 않는다.

- 이번 버그 테스트는 첫날/다음 날을 모두 명시적으로 주입하고 KST 자정 전후에 예산이 분리되는지 검사한다. 시스템 시계나 실제 운영 환경 변수를 바꾸지 않는다.
- 날짜 가상화 실행을 테스트 전용 보조 runner로 정리한다. common.today뿐 아니라 테스트가 사용하는 현재 UTC/KST 읽기 지점이 무엇인지 명시하고 동일 시나리오 안에서 서로 다른 실제 시계가 섞이지 않게 한다. 과거 fixtures를 무조건 현재 날짜로 고치는 것도 금지한다.
- CI에서 일반 Windows/Ubuntu 회귀 유지. 추가 Linux job에 테스트 전용 날짜 2026-09-26, 2026-10-20, 2027-02-15 및 KST 연말 자정 경계를 넣는다. 실제 미래 날짜를 환경변수에 적기만 하고 코드가 읽지 않는 가짜 검증이 되면 안 된다. runner가 의도한 시각을 사용했음을 별도 작은 시험으로 확인한다.
- production 코드에 날짜 우회용 환경변수를 추가하지 않는다. 새 matrix는 push/PR 검증용이며 매일 수집 job에서 matrix를 반복하지 않는다.
- 사고 기록에 최초 실패/발견/복구 시각, 미실행 단계, 복구 실행 ID를 남긴다. 실패 run 수를 실제 확인한 범위로 적고, 수집 중단 기간에 관측하지 못한 값을 소급 관측으로 만들지 않는다.

완료: 최초 날짜 버그를 다시 넣었을 때 신규 CI 시간 시나리오가 검출하고, 현재 코드가 일반/가상 날짜 전체를 통과한다. README에 재현 명령 1개를 남긴다.

## 3. I2 — 기업별 원문 품질 표시

대상 candidates.context_inputs/build/card_lines, template, schema의 관측 계약, 관련 테스트. 현재 단계 품질에는 partial이 있지만 개별 카드에 전달되지 않는다. 원문 일부 접근 실패가 없는 것처럼 보이지 않도록 한다.

- research/source 품질과 screen 숫자 품질은 별도 필드로 유지한다. 후보별 source_quality=complete/partial/unavailable/unknown, 실패 문서 수와 이유, last_attempt_at, last_valid_context_id/observed_at를 전달한다. 예외 문자열에 비밀 URL이 포함되지 않게 한다.
- 일부 문서만 실패: 확보한 근거는 표시하되 '공식 원문 일부 미확보 — 확보된 자료 기준'을 해당 구역 바로 위에 표시한다. 전부 실패: '최근 원문 확인 실패'와 마지막 유효 근거 날짜를 표시한다. 접근 실패를 '관련 발표 없음'으로 바꾸지 않는다.
- 과거 카드 재현을 위해 품질/시도시각은 관측 기록에 보존한다. 기존 OB/CV/CTX를 수정하지 않는다. 시장 관측일과 자료 조사일을 혼동하지 않는다. 변경에 따른 생성기/스키마 버전을 명시한다.
- 새 원문 조사 실패나 partial만으로 기존 사람 승인 자체를 삭제하지 않는다. 현재 화면에는 당시 승인과 최신 자료 제한을 같이 보여 준다. partial 자료로 새 자동 추천을 만들지 않는 기존 원칙은 유지한다.
- Telegram/Markdown/HTML에 동일한 의미가 나와야 한다. 운영 자료 사본의 실패 상태만 바꾼 모의 화면과 실제 운영 자료 화면을 구분해 확인한다.

시험: 정상→일부 실패→전부 실패→회복, stale screen과 source partial 동시 표시, FY 변경 시 옛 초안 오연결 방지, 과거 관측 불변, 자료 제한이 있어도 /track 사용자 선택 의미 유지.

## 4. I3 — v3 초안 평가, API를 더 쓰지 않고 준비

- 먼저 tests/test_h_followup.py RealOutputTest에 저장된 실제 출력과 원문 블록을 현 검증기에 재입력한 **오프라인 재검증 표**를 만든다. 기업/문장별로 이전 거부 사유, 새 수용 여부, 수치·단위·기간·주체 대조 결과를 기록한다. 잘못된 $915.0→$906.4 사례는 계속 거부되어야 한다.
- 남아 있는 출력이 짧게 잘린 excerpt뿐이면 완전한 원응답이라고 재구성하지 않는다. 그 사례는 'fixture 범위만 검증'으로 표시한다. 이 시험 결과를 새 운영 초안으로 저장하거나 과거 날짜로 소급하지 않는다. API 예산은 추가하지 않는다.
- 다음 정상 실행에서 v3 요청 수/실패/보류/수용 문장/핵심 초안을 각각 집계한다. 여섯 요청이 여섯 기업 성공을 뜻하지 않는다. 같은 기업 실패 재시도 때문에 다른 후보가 계속 밀리지 않는지도 확인한다.
- 실제 수용 초안은 모두 원문과 대조하되 최대 6기업 범위만 검토한다. 각 초안에 '후보 기업의 어떤 지표가 어떻게 바뀌었는가', '일회성·반대 근거', '컨센서스 상향과의 연결 미확인'이 보이는지 기록한다. 자회사 배당 등 관련이 약한 문장을 수용률 개선을 위해 핵심 근거로 올리지 않는다.
- 성공 개수 목표에 맞추려고 숫자·기간 검증을 완화하지 않는다. 0건이면 실패를 세 가지(제공자 실패, 정상 출력의 과잉 거부, 자료 자체가 부적합)로 나눠 원인별 한 번의 표적 수정만 진행한다. 제공자 장애는 구조 변경 이유로 삼지 않는다.

운영 인수 조건: 제공자 요청/차감이 일치하고, 새 검증기의 실제 출력에서 최소 하나의 유용한 후보 기업 이익 설명을 원문 대조로 확인하며, 그 실행의 모든 수용 문장에 중요한 수치·주체·기간 오류가 없어야 한다. 이는 전체 투자 판단 정확도 보장이 아니라 최소 작동 증거다. 충족하지 않으면 '초안 실용성 미확인' 상태를 유지한다.
