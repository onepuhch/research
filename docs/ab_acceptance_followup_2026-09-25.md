## 판정

A·B의 주요 개선은 확인했다. 로컬 테스트 91개 통과. 운영 스냅샷 `20260925T000839Z_36076125470-1.json.gz`에서 EPS 2,429 정상 / 866 자료 부족, 후보 103개, 업종 102개, 상위 가격 비교 30/30, 기술적 실패·미시도 0을 확인했다. 실행 시간은 14분 37초다. 이전 ‘후보 업종·가격 전부 누락인데 성공’ 문제는 이 실행에서 해소됐다.

아래 잔여 경로는 보완해야 하므로 A·B의 모든 예외 처리가 완료됐다고 판정하지 않는다. 이번 검토는 저장된 운영 증거와 코드, 오프라인 테스트를 대상으로 했으며 새 운영 실행·전송은 하지 않았다. 최신 저장 returns 상태는 degraded다. b00f035 수정의 배포 후 운영 성공은 아직 확인하지 않았다.

## 설계 변경에 대한 결정

1. **요청 간격:** workers=3, 최소 0.25초와 429 감속을 잠정 유지한다. 원 지시의 0.5초는 3,295회만으로 약 27.5분이 필요해 25분 예산과 모순이었다. 설계상 계산 누락을 정정한다. 한 번 성공했다고 지속적인 접근 가능성을 보장하지 않으므로 이후 실행의 시간·429·미시도 수를 계속 기록한다. 실패 시 속도를 더 올리지 않는다.
2. **보존:** 후보만 남기지 않는다. 비후보도 이후 조건 평가와 누락 분석에 필요하다. 현재 전체 스냅샷은 유지하고 자동 삭제는 도입하지 않는다. 추가 저장량 약 160MB/년이라는 추정은 합리적이나 실패·재실행 횟수에 따라 달라진다. 30일 누적 시 실제 증가량과 clone 시간을 측정해 별도 저장소 이전을 설계한다. 향후 이전은 전체 객체 복사 → 체크섬 검증 → 복원 시험 → 포인터 전환 순서로 하며, Git 이력 강제 재작성은 이 작업에 포함하지 않는다.
3. **ALAB 경계값:** 특정 종목을 넣기 위해 상향 조건을 느슨하게 바꾸지 않는다. 현재 `cur > d30`는 유지한다. 별도 보조 분류가 필요하면 `abs(cur-d30) <= max(0.0001, abs(d30)*0.0001)`를 ‘30일 보합’으로 표시하되 신규 상향 후보에 합치지 않는다. 이 허용치는 검증된 투자 법칙이 아닌 표시 정책이며 설정·버전·등록일을 기록한다. ALAB는 기존 추적 종목이므로 신규 후보 제외가 추적 중단을 뜻하지 않는다.
4. **중간 결측:** 스크리너가 빈 날을 채우지 않고 실제 사용 날짜를 남기는 방식은 유지한다. 다만 시작·종료 가격의 신선도와 세션 종료를 검증해야 한다. 성과 복기에서 중간 결측을 엄격히 거절하는 기존 정책은 별도로 유지한다.
5. **시장 해석:** AXTI의 EPS와 주가 변화는 저장된 제공자 자료의 스크리닝 결과로만 다룬다. EPS가 ‘3배가 됨’은 +200%이며 ‘+300%’와 구별한다. 대상 기간·실제 주가 날짜·출처·회계기준 미확인 한계를 함께 표시하며 저평가나 선행 발견 성공으로 단정하지 않는다.

## 다음 구현 지시 — A·B 보완 후 C

### AB-1. HTTP 성공과 실제 비교 가능 상태 분리

위치: `screen_revisions.py`의 fetch_profile, chart, screen, stage_stats.

- 현재 profile의 HTTP 200 응답이 빈 객체여도 industry=None인 success가 될 수 있다. 유효한 응답이지만 업종이 없으면 unavailable/profile_missing으로 전환한다.
- price_comparison이 chart_mismatch/no_prices/window_not_covered를 반환해도 price 단계는 기존 fetch success를 그대로 센다. 후처리 검증 결과를 단계 상태에 반영한다.
- 티커/통화 불일치와 구조가 잘못된 응답은 failed, 정상 응답의 짧은 상장 이력 등 비교 자료 부족은 unavailable로 구분한다. split_in_window로 PER만 미산출하는 경우 주가 비교 자체는 success다.
- chart의 HTTP 200+error를 전부 unavailable로 처리하지 않는다. Not Found만 unavailable, 그 외 서비스 오류는 failed로 분류한다. 다른 모듈과 같은 규칙을 쓴다.
- requested = success+unavailable+failed+not_attempted를 유지하고, 화면의 가격 성공 건수는 실제 price_pct_90 산출 건수와 일치시킨다.
- 테스트: 빈 프로필, 잘못된 티커 chart, 정상 응답+가격 없음, 상장 이력 부족, HTTP 200+서비스 오류, 분할로 PER만 미산출. 부분 결과는 보존한다.

### AB-2. 완료된 거래일과 가격 신선도 검증

위치: price_comparison 및 테스트. 기존 research_returns.close_time의 지원 연도 범위와 달력을 재사용하거나 공통 함수로 옮기되 두 곳에서 서로 다른 달력을 만들지 않는다.

- 현재 `timestamp <= as_of`는 일봉 시작 시각만 확인하므로 장중 봉도 종가처럼 포함할 수 있다. 세션 마감+1시간이 as_of 이전인 봉만 사용한다. 지원하지 않는 시장/달력은 추정하지 말고 미산출 사유를 남긴다.
- timestamp/close/adjclose 배열 길이, 정렬, 중복, 유한값을 검사한다. zip으로 잘린 배열을 정상 전체 응답으로 취급하지 않는다. 조정값만 없으면 원시 종가 비교는 가능하되 조정수익률만 미산출한다.
- 90일 기준일은 현재 기준일에서 90일 전인 날짜로 정하고 그 날짜 이하의 마지막 유효 종가를 선택한다. 기준 날짜와 실제 선택 날짜를 모두 남긴다.
- 정책 초기값: 종료점은 기대되는 마지막 완료 거래일보다 최대 1거래일 이전, 시작점은 90일 기준일 이전 최대 7달력일까지만 허용한다. 초과하면 stale_price로 unavailable. 휴장일은 종료점의 거래일 지연에 포함하지 않는다. 값은 policy에 둔다.
- 테스트: 장중 실행, 마감 직후, 주말/휴장일, 마지막 봉 결측, 오래된 시세, 시작점 공백, 배열 길이 불일치, 기존 가격/분할 테스트 유지.

### AB-3. 요청 시간 제한과 연결 예외 마무리

위치: Yahoo.get_json/find_crumb, Pacer, run_stage, SEC 준비 단계.

- get_json은 pacing 대기 전에만 예산을 확인한다. wait 이후에도 남은 예산을 확인하고, 만료됐으면 네트워크 호출 없이 not_attempted로 처리한다. 전송 timeout은 남은 시간 이내로 제한한다.
- 세션 준비/갱신과 SEC 다운로드도 http.client.HTTPException 계열(IncompleteRead 등)을 처리한다. 현재 get_json에 추가된 처리만으로 준비 단계까지 보호되지는 않는다. 세션 갱신도 남은 예산 안에서 수행한다.
- 예외가 get_json 이후 모듈 검증에서 발생하면 thread-local 시도 수를 버리고 error.attempts만 쓰는 경로가 있다. 둘 중 확인 가능한 큰 값을 사용해 429→200+API error 같은 실패에서도 실제 시도 수를 보존한다. 실제 전송 0회는 0으로 남긴다.
- 정책상 시도 한도를 명확히 한다. 현재 max_attempts=3은 한 패스 기준이며 실패 목록 재조회까지 총 6회가 가능하다. 문서·설정 설명에 두 패스의 상한을 적고 전체 시간 한도를 우선한다.
- 테스트: pacing 중 예산 만료 후 호출 0회, 세션/SEC 본문 읽기 중단, 재시도 후 API error의 누적 시도 수, 두 패스 최대 호출 수. 가짜 시계/transport로 실행한다.
