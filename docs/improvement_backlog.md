# 발굴 엔진 개선 백로그 (목적 정렬)

점검일 2026-06-07. Claude(개념) + Codex(코드레벨) 점검 통합.

**현 진단**: 자동 수집·저장·알림 인프라는 견고(기반 ~8/10)하나, 목적인 "조기 발굴 엔진"으로는 부족(목적적합도 ~4/10). 지금은 *병목 발굴기*가 아니라 *공시·뉴스 분류기*에 가깝다. **P0를 먼저 고치지 않으면 데이터가 쌓일수록 노이즈가 더 빨리 누적된다.**

우선순위: P0(오염 차단) → P1(발굴 루프 닫기) → P2(점수·단계 신뢰성) → P3(병목 지도=목적의 심장) → P4(검증).

## P1 — 발굴 루프 닫기

- [ ] **EPS 상향률 vs 주가 상승률(동일기간) 계산** ← PRINCIPLES §2의 밸류 판단 핵심. 현재 주가 데이터를 안 가져와 비교 불가. → 주가 변화율 수집해 동일기간 EPS 리비전율과 대조.
- [ ] **promote 원신호 연결·중복 방지** — `promote.py`가 origin_signal_id·출처URL을 리뷰로그에 안 남김. 같은 신호 /track 반복 시 idea_id 계속 생성. 기본값(유형=병목확산형, 근거강도=2) 고정. → origin_signal_id 기록 + 동일 종목 중복 승격 차단 + 기본값 입력화.
- [ ] **/track ↔ eps_watchlist 자동 연결** — 승격 종목이 자동 EPS 추적 안 됨(watchlist 수동). → promote 시 watchlist 자동 추가.
- [ ] **EPS 연속성 정상화** — 값 미변경 시에도 "유지" 행이 쌓이고, `gen_report.py`가 상향→상향→유지를 연속 0회로 계산. → 값 미변경 행 skip + 연속 상향 카운트 수정.
- [ ] **알림 날짜경계 재시도** — `notify.py`가 "오늘 신호"만 선택. 당일 전송 실패 후 다음날엔 미전송분이 누락. → 미전송(pushed 아님) 신호는 날짜 무관 재시도.

## P2 — 점수·단계 신뢰성

- [ ] **축별 근거 저장 + 결정론 검증** — 프롬프트가 축 이름만 주고 축별 판정기준·인용근거를 요구 안 함. 반환된 축은 합계만 저장 후 폐기. enum만 맞으면 Gemini 결과 그대로 신뢰. → 축별 근거(인용) 저장, 근거 없으면 0 강제.
- [ ] **단계 판정 시계열 기반** — 단일 기사로 "중기"도 가능. 단계는 EPS 다개월 연속·선행지표 개수가 필요. → 단일 항목은 최대 "초기"로 제한, 단계는 metric_log 시계열에서 산출.
- [ ] **반복 등장 종목 강화** — 같은 종목이 여러 날 신호 떠도 따로 쌓임. → 누적 등장 카운트 → "자꾸 나오는 종목" 승격 후보로 표시.

## P3 — 병목 지도 (목적의 심장)

- [ ] **밸류체인·병목 클러스터링 → bottleneck_log 자동 생성** — 현재 항목 1개=테마 1개일 뿐, 여러 회사·공급망 신호를 묶어 "병목이 GPU→전력→광통신으로 이동 중"이라 판단하는 과정이 없음. → 밸류체인 지도(config) + 다중 신호 클러스터링 + 이동 구간 가중 + `bottleneck_log` 연결. **설계 신중히(자동 vs 큐레이션).**
